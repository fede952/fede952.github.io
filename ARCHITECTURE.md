# Architecture

Static Hugo site (Extended 0.168, PaperMod theme as a git submodule) deployed to GitHub Pages by
`.github/workflows/production.yaml`. Six languages, all in subdirectories: `/en/ /it/ /es/ /de/ /fr/ /pt/`.

## Content model

| Path | What | Layout |
|---|---|---|
| `content/tools/<tool>/index.<lang>.md` | One page per tool: front matter + long-form copy | see "Tool pages" |
| `content/tools/games/<game>/` | Browser games | `layout: game` or tools/single |
| `content/learn/<sub>/<page>/` | guides, cheatsheets, interviews, roadmaps, writeups, debug-sys | `_default/single.html` |
| `content/about|contact|privacy|cookies|stack|links|projects/` | Site pages | various |
| `content/apps/pasta-stack/privacy/` | Live privacy policy of a mobile app — **do not move or delete** | `_default/single.html` |

The English file is `index.md` (no suffix); translations are `index.<lang>.md` in the same bundle, so Hugo links them
as translations automatically.

## Tool pages

The interactive part of a tool is either a self-contained HTML app in `static/tools/<tool>/index.html` (or
`static/games/<game>/`), embedded with an `<iframe>` (`tool_file` front matter), or an inline partial in
`layouts/partials/tools/` (`tool_partial`). Apps are `noindex` with a canonical pointing to the parent tool page, take
their UI language from `?lang=`, and never send user data anywhere. The disclosed exceptions, each triggered only by an
explicit button and named on the tool and on the 6 privacy pages, are NetGuard (ipwho.is), PassFort's breach check
(api.pwnedpasswords.com) and the SPF/DKIM/DMARC Checker (DNS-over-HTTPS to cloudflare-dns.com);
`tests/privacy-guard.mjs` fails on any other `fetch()` host. Tool logic that can be tested without a DOM lives in
`static/js/tools/*.mjs` with unit tests in `tests/unit/`; heavy libraries (Tesseract, hash-wasm, pdf.js…) are
self-hosted in `static/vendor/` and loaded only when used. Apps that read the parent page (quiz `?score=`, CVSS
`?vector=`) do so through `window.parent.location` (same origin). The Encrypted Message Link targets the standalone
app URL, not the tool page, so its `#fragment` never shares a page with ads or analytics. Templates: `layouts/tools/single.html` (every tool page) and `layouts/_default/game.html` (`layout: game`).

Tool, game and learn pages use `.page-grid`: the article plus `partials/sidebar.html` (related tools from
`partials/related-tool-pages.html` — `data/related.yaml` picks, then `.Related` on tags, then the newest; related guides
from `data/related.yaml` or more articles of the same section; the sidebar ad). At ≥ 1100 px the sidebar is a 300 px
column, below that it follows the article.

Every tool has a category and an icon in `data/tool_icons.yaml` (`partials/page-meta.html` resolves them for any page,
`partials/icon.html` renders the inline SVG). `partials/tools-by-category.html` groups the tools for the home page and
`/tools/`; `partials/card.html` is the one card used by every listing; `partials/filter-bar.html` + `assets/js/site.js`
give `/tools/` and `/learn/` their chips and text filter.

## Design system

- `assets/css/extended/tokens.css` is the only place with colour, space, type, radius, shadow and focus values
  (contrast notes in its header). PaperMod's variables are mapped onto it. All other stylesheets in
  `assets/css/extended/` use tokens only; PaperMod bundles them into the single fingerprinted stylesheet.
- The embedded apps load `/css/tool-base.css`, generated by `partials/tool-base.html` from `tokens.css` +
  `tool-ui.css` + `assets/css/tool-app.css` (stable URL, not fingerprinted). Each app maps its own variable names onto
  the tokens in its `:root`; `--tool-accent` is the only per-app colour (logo mark).
- `assets/js/site.js` (deferred, fingerprinted): header menus, back-to-top, code-copy, horizontal-scroll fades,
  listing filters, the sidebar ad slot.
- Markdown render hooks: `_markup/render-codeblock.html` (header bar + Copy), `render-table.html` (scrollable region),
  `render-image.html` (WebP, dimensions, lazy).

## Monetization

**AdSense.** `extend_head.html` loads `adsbygoogle.js` on every page except 404 (it also injects Google's consent
banner, which the footer "Cookie Settings" link reopens). Manual units are config-driven:

- `[params.ads]` in hugo.toml: `client`, `slot_default`, and one `slot_<position>` per position. An empty slot falls
  back to `slot_default`.
- `partials/ads/enabled.html`: the allowlist. Only single pages in `tools` and `learn` get units; `noads: true` opts out.
- `partials/ads/unit.html`: one responsive unit in a CLS-safe reserved-height container (`ad-slot.css`).
- `partials/ads/inject-content.html`: learn pages get `article_mid` before the 2nd and 5th `<h2>`; tool pages before the 2nd
  (after the how-to, when enough text precedes it). The quiz's questions live inside its iframe, so no unit can land
  between them. `tests/ads.mjs` enforces ≥ 150 px between any unit and a tool control.
- Tool templates place `tool_top` under the intro and `tool_after` after the tool (max 3 units per page).
- `{{< ad-banner position="…" >}}` places a unit manually in markdown.

**Affiliate.** `partials/affiliate/block.html`, inserted by `layouts/tools/single.html` after "How it works".
`[params.affiliate]` holds one partner (`<category>_name`, `<category>_url`) per category (password_manager, vpn,
privacy, devsec) and `[params.affiliate.tools]` maps tool → category; a block renders only when name and URL are both
set. Links are `rel="sponsored noopener"` with a visible localized disclosure (`aff_*` i18n keys).

## Head, privacy, security

- Meta CSP is minimal on purpose (`upgrade-insecure-requests; object-src 'none'; base-uri 'self'; form-action 'self'`).
  Host allowlists broke AdSense, whose creative hosts rotate. Full security headers live in `static/_headers`
  (applied by Cloudflare Pages; GitHub Pages ignores the file).
- Analytics: Umami, cookieless, production builds only. No Google Analytics.
- Fonts (`static/fonts/`) and JS libraries (`static/vendor/`) are self-hosted; no third-party CDN.
- `layouts/partials/extend_head.html` also emits the hreflang `x-default` (PaperMod emits the per-language ones).
- Structured data: `layouts/partials/templates/schema_json.html` (everything built with `dict | jsonify`). One Person
  from `[params.person]` is author/publisher everywhere; tools get WebApplication + FAQPage (from front matter `faq`),
  learn pages TechArticle, About a ProfilePage, home WebSite + SearchAction (`/<lang>/?q=`). Learn pages also render
  breadcrumbs, a byline and `partials/author-box.html` from the same params.

## Share cards (Open Graph)

Tool, game and learn pages get a per-page 1200×630 PNG built at build time by `partials/og/card.html` with Hugo's
`images.Text` / `images.Overlay` over `assets/og/bg.png` and the page's icon tile from `assets/og/icons/` (fonts in
`assets/og/fonts/`), published at `/og/<lang>/<path>.png`. `partials/templates/opengraph.html` and
`twitter_cards.html` override PaperMod's to use it. Run `node scripts/og-assets.mjs` after adding an icon to
`data/tool_icons.yaml` (it renders the background and icon tiles with Playwright). The Phishing Quiz also publishes
`/<lang>/tools/phishing-quiz/score/<n>/` pages (`partials/quiz/score-pages.html`), one share card per score, which
redirect to the quiz with `?score=n`. `tests/static-checks.mjs` checks every card exists and is 1200×630.

## Search, sitemap, redirects

- Search: `layouts/_default/index.json` builds a per-language JSON index of regular pages (labelled with the localized
  content type); the command palette in `extend_footer.html` loads it lazily with Fuse.js (header search button,
  Ctrl/Cmd+K, `?q=`).
- Sitemap: `layouts/_default/sitemap.xml`, skips pages with `robotsNoIndex` (tag/category listings, via the
  `cascade` in `hugo.toml`).
- Old URLs: front-matter `aliases` (relative to the page's language) produce meta-refresh pages, and Hugo also
  generates `public/_redirects` from them (`layouts/home.redirects`) with 301s for Cloudflare Pages, plus rules for
  the removed languages and news section. On GitHub Pages a small script in `static/404.html` covers the rest.
- Headers: `static/_headers` (Cloudflare Pages only); see README → Cloudflare.

## Caching

`partials/footer.html` is `partialCached` in `baseof.html` keyed by `.Layout .Kind .Section` (+ two params, and
implicitly the language). Anything inside the footer may only depend on those inputs.

## Build and tests

```bash
hugo --gc --minify     # → public/   (~8 s)
npm install && npx playwright install chromium   # once; test harness only
npm test               # static checks, functional suite, tool-page audit, visual layout checks
node tests/overflow-sweep.mjs 360                # every page at 360 px
```

All tests run against the local build with every external request blocked (`tests/lib/server.mjs`); see
REDESIGN_REPORT.md → Phase 0.

CI and Cloudflare Pages both pin `HUGO_VERSION=0.168.0` and need submodules checked out.
