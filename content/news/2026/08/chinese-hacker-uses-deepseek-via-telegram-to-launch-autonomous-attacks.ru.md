Unit 42 сообщает о китайскоязычном threat actor, использующем DeepSeek через Hermes Agent для автономных атак на системы, доступные из интернета, после одной команды в Telegram.

{{< cyber-report severity="High" source="The Hacker News" target="Системы, доступные из интернета" >}}

Palo Alto Networks' Unit 42 раскрыла новую цепочку атак, в которой китайскоязычный threat actor, отслеживаемый под псевдонимами knaithe и KnYuan, использовал модель ИИ DeepSeek через фреймворк с открытым исходным кодом Hermes Agent для проведения автономных атак. Операция началась с одного указания в Telegram, после чего агент самостоятельно выявлял системы, доступные из интернета, и выбирал подходящие публичные эксплойты.

{{< ad-banner >}}

По словам исследователей, во время сеанса не было обнаружено дальнейшего ввода оператора, что указывает на высокую степень автоматизации. Это знаменует собой значительную эволюцию кибератак с помощью ИИ, когда агент ИИ выполняет разведку, выбор эксплойтов и их запуск без постоянного контроля со стороны человека.

Эти выводы подчеркивают растущую угрозу автономных атакующих инструментов на основе ИИ, которые снижают порог входа для менее квалифицированных злоумышленников и увеличивают скорость и масштаб операций. Организации должны адаптировать свою защиту для противодействия таким автоматизированным угрозам, которые могут действовать на машинной скорости и адаптироваться к окружающей среде.

Этот инцидент подчеркивает острую необходимость для SOC отслеживать модели атак, управляемых ИИ, такие как быстрые автоматизированные попытки эксплуатации, которые могут не иметь типичных признаков человеческих ошибок. Команды DevSecOps должны уделять первоочередное внимание укреплению активов, доступных из интернета, и внедрению автоматизированных механизмов обнаружения и реагирования для противодействия автономным угрозам. Кроме того, рассмотрите возможность ограничения доступа к моделям ИИ и мониторинга необычного использования API, которое может указывать на атаки с использованием ИИ.
